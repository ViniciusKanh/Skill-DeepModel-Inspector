## Description

DeepModel Inspector gives your coding agent a forensic toolkit for LLM work. Instead of guessing from a loss plot or a
handful of samples, the agent runs deterministic analyses on your own artifacts — training logs (CSV/JSONL or
`trainer_state.json`), datasets (text, instruction, chat messages, CSV), tokenizations, generated outputs and run
configs/metrics — and returns findings that carry evidence, a status and a way to confirm them.

Every conclusion is labelled `CONFIRMED` (a documented rule is satisfied by the data), `POTENTIAL` (indicators that
need confirmation) or `INCONCLUSIVE` (not enough information). Root-cause hypotheses are never presented as proven;
each comes with the experiment that would confirm or reject it. No fake confidence percentages.

### Main features

- **Training health:** NaN/Inf, divergence, overfitting (train↓ while eval↑), underfitting, plateaus, loss spikes,
  LR–spike association, gradient explosion/vanishing (when grad_norm is logged), slopes, window stability, perplexity.
- **Dataset quality:** exact and MinHash near-duplicates, empty/malformed records, chat/instruction schema errors,
  mojibake and control characters, internal repetition, heuristic language estimate, instruction-like content in data.
- **Contamination:** exact, near-duplicate, prompt-only and 13-gram overlap between train and eval splits, with
  template n-grams excluded and within-split duplication kept separate from leakage.
- **Tokenizer efficiency:** tokens/word, fragmentation, byte-fallback, UNK, truncation and context waste, and
  cross-tokenizer comparison — from your real tokenizations, never simulated.
- **Generation behaviour:** distinct-1/2/3, repetition, MATTR, truncation, redundancy across prompts, bootstrap
  comparison between decoding configs, lexical grounding against references you provide.
- **Experiment comparison:** hyperparameter diff, metric regressions with direction, and a compatibility guard that
  refuses to compare perplexities across different tokenizers or eval sets.
- **Root-cause engine:** answers questions in English or Portuguese, ranks hypotheses, lists experiments and tells you
  exactly which files are missing.
- **Reports:** JSON, Markdown and static HTML with 11 standard sections.

### Who it is for

ML engineers fine-tuning LLMs (SFT, LoRA/QLoRA), researchers training small models, MLOps teams preparing datasets and
evaluations, and developers debugging generation quality.

### Why it is different

- Evidence first: each finding cites the numbers and file it came from, plus how to confirm it.
- Honest by design: refuses to diagnose overfitting without validation loss, to infer gradients from loss, or to
  compare incompatible perplexities.
- Private and safe: runs locally, read-only, no network, no environment reads, no pickle loading, credential files
  refused, evidence snippets redacted, data never treated as instructions.
- Lightweight: Python 3.11+ standard library only; CPU; no model downloads.

## See it in action (real output from the bundled synthetic demo)

**Request:** "Why is my LLM repeating the same sentences?"

**Files analyzed:** `logs/training_log.csv`, `data/train.jsonl`, `data/test.jsonl`, `outputs/generations.jsonl`,
`tokenization/tokenized_pt.jsonl`, `runs/run_v1`, `runs/run_v2` (synthetic, generated by a seeded script).

**Answer status: CONFIRMED** — degenerate repetition is observed; its causes are reported as hypotheses.

- DMI-005 HIGH/CONFIRMED *Degenerate repetition*: 30 of 30 responses repeat more than half of their word 3-grams
  (mean repetition rate 0.84); decoding used temperature 0.0, repetition_penalty 1.0, do_sample False.
- DMI-011 MEDIUM/CONFIRMED *Responses cut by the token limit*: 15 of 30 (finish_reason = length).
- DMI-004 HIGH/CONFIRMED *Exact duplicate records* in the SFT data: 30 extra copies (11.5% of 260 records).
- Hypotheses (POTENTIAL): repetitive/duplicated targets (HYP-006); loop-prone decoding (HYP-007); missing EOS
  supervision (HYP-008) — each with a one-variable test, e.g. "Re-generate the same prompts with
  repetition_penalty=1.15 or temperature=0.7 (one change at a time)".

The same audit also found: 10 of 20 test records verbatim in train (CRITICAL/CONFIRMED) plus 5 near-duplicates and 3
reused prompts; an overfitting pattern (best eval loss 1.108 at step 400, final 1.485, +34%); a regression between runs
(eval_accuracy 0.71 → 0.66, eval_loss 1.20 → 1.34) with learning rate (2e-5 → 1e-4) and epochs (3 → 5) listed as
candidate causes; and a tokenizer costing 3.94 tokens/word with 20% byte-fallback tokens on Portuguese text.

## Requirements / compatibility note

Python 3.11 or newer (standard library only). Runs on CPU, offline. The agent must be allowed to run Python
scripts and read the files you point it to. Verified on Linux (Python 3.11 and 3.13); Windows verification pending.

## Limitations

Lexical (not semantic) duplicate, leakage and grounding checks; hallucination checks only against references you
provide; thresholds are documented heuristics; single-run comparisons do not prove significance; tokenizer analysis
requires your tokenizations; near-duplicate search capped at 20,000 records per file; weights are never loaded.

## FAQ

**Does it need a GPU, internet or an API key?** No.
**Does it upload my data?** No. Scripts make no network calls and only read the files you pass.
**Can it detect hallucinations?** Only relative to a `reference` text you provide per output; flagged sentences are candidates.
**Which training frameworks?** Any that can export loss per step to CSV/JSONL; Hugging Face `trainer_state.json` is read directly.
**Does it load my checkpoints?** It reads only safetensors headers and JSON configs; pickle files are never opened.
**Why "INCONCLUSIVE"?** Because a required artifact is missing (e.g. no validation loss); the report says which file to add.
**Can I get reports in Portuguese?** Report headings support `--lang pt`; findings text is in English.
